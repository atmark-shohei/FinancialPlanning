# 配当履歴アーカイブ

証券会社ごとの配当CSVを保存し、重複なく統合して計画線と突合する。

## ディレクトリ構成

```
data/dividends/
├── README.md          このファイル
├── dividends.csv      ★正規化・重複排除済みの統合ファイル（自動生成）
└── raw/
    └── <年>/
        ├── rakuten_20260905.csv
        ├── nomura_20261231.csv
        └── sbi_20261231.csv
```

`dividends.csv` は **スクリプトが毎回作り直す**。手で編集しない。

## 取り込み手順

### 1. CSVを置く

```
data/dividends/raw/<年>/<証券会社>_<ダウンロード日>.csv
```

| 項目 | ルール |
|---|---|
| 証券会社 | `rakuten` / `nomura` / `sbi` のいずれか（**先頭に必ず付ける**。これで形式を判別する） |
| 日付 | `YYYYMMDD`。ダウンロード時点が分かるようにする |
| 年フォルダ | 配当の発生年。ダウンロード日の年ではない |
| 文字コード | **BOM付きUTF-8に変換する**（下記） |

楽天証券のCSVは Shift-JIS（CP932）で出力される。そのままだとGitHub上で文字化けする。

```bash
printf '\xEF\xBB\xBF' > data/dividends/raw/2026/rakuten_20260905.csv
iconv -f CP932 -t UTF-8 ~/Downloads/dividendlist_20260905.csv >> data/dividends/raw/2026/rakuten_20260905.csv
```

### 2. スクリプトを実行する

```bash
node scripts/import-dividends.mjs
```

- `raw/` 配下のCSVを**全部**読み直して `dividends.csv` を作り直す
- 重複を自動で除外する
- 年別集計と計画線との乖離を表示する

### 3. コミットする

`raw/` のCSVと `dividends.csv` の両方をコミットする。

## 重複はどう防いでいるか

同じ配当が複数のCSVに現れても1件に統合される。判定キーは次の5つの組み合わせ。

```
入金日 | 証券会社 | 銘柄コード（無ければ銘柄名） | 口座区分 | 受取金額
```

**同じ銘柄でも口座区分が違えば別の配当**として扱う。
例: 2026/07/17 の 2559 は「特定・一般」と「NISA成長投資枠」で2件あり、どちらも残る。

### これで防げること / 防げないこと

| ケース | 結果 |
|---|---|
| 期間が重なるCSVを何度もダウンロードして置く | ✅ 除外される |
| 同じCSVを別名で2回置く | ✅ 除外される |
| 3社のCSVを別々に置く | ✅ 証券会社が違うので共存する |
| 同一日・同一銘柄・同一口座・**同一金額**の配当が本当に2件ある | ⚠️ 1件に潰れる（実務上ほぼ起きないが、起きたら手で確認する） |

## 証券会社を追加するとき

`scripts/import-dividends.mjs` の `BROKERS` に列名を書く。**野村證券とSBI証券は未設定。**

```js
nomura: {
  label: '野村證券',
  header: '受渡日',                    // 見出し行に必ず含まれる文字列
  cols: {
    date: '受渡日', account: '口座区分', code: '銘柄コード', name: '銘柄名',
    gross: '配当金額', tax: '所得税', net: '受取金額',
  },
},
```

初回のCSVを入手したら**見出し行をそのまま写す**だけでよい。
未設定のまま実行しても、スキップされて警告が出るだけで既存データは壊れない。

## 計画線との突合

スクリプトが `FIRE_Strategy.md` 第9.7節の計画線と自動比較する。

| 年齢 | 年 | 計画（税引前） | 計画（手取り） |
|---:|---:|---:|---:|
| 32 | 2026 | 770,183 | 613,721 |
| 33 | 2027 | 770,183 | 613,720 |
| 34 | 2028 | 875,931 | 697,986 |
| 35 | 2029 | 984,835 | 784,766 |
| 36 | 2030 | 1,096,989 | 874,136 |
| 37 | 2031 | 1,212,492 | 966,174 |
| 38 | 2032 | 1,331,442 | 1,060,959 |
| 39 | 2033 | 1,453,943 | 1,158,574 |
| 40 | 2034 | 1,580,102 | 1,259,104 |

判定基準は `FIRE_Strategy.md` 第14.2節に合わせている。

| 達成率 | 判定 | 対応 |
|---|---|---|
| 95%以上 | ✅ 計画線どおり | なし |
| 85〜95% | 🟡 −5〜15% | 翌年の高配当への配分を見直す |
| 85%未満 | 🔴 −15%超 | FIRE時期を1〜2年後ろ倒しする前提で再計算 |

**進行中の年は「進行中」と表示され、判定されない。** 12月末のCSVが揃ってから判定する。

計画線を変更したら、`scripts/import-dividends.mjs` の `PLAN` も直すこと。

## 副次的な使い方 — 売却済み銘柄の発見

配当履歴に出てくるが `Asset.md` の保有一覧にない銘柄＝**権利確定後に売却したもの**。
毎年の突合でこれをチェックする。NISA枠の銘柄なら、簿価分が翌年に復活する（第7.7節）。

| 年 | コード | 銘柄 | 口座 | 受取配当 |
|---|---|---|---|---:|
| 2026 | 3002 | グンゼ | NISA成長投資枠 | 21,600 |
| 2026 | 3031 | ラクーンホールディングス | 特定・一般 | 5,100 |
